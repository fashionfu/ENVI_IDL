## 一、概述

- **服务器 IP**: 192.168.0.19
- **GSF 服务端口**: 9191
- **Node.js 安装路径**: `D:\Program Files\nodejs\`
- **ENVI 安装路径**: `D:\Program Files\NV5\ENVI61\`
- **项目目录**: `D:\GSF32\`
- **任务文件目录**: `D:\Program Files\NV5\ENVI61\custom_code\[TaskName]\`

### 1.2 移植内容

- Node.js 脚本文件（调用 GSF API）
- ENVI Task 任务文件（.task 和 .pro 文件）
- 数据文件路径配置
- 环境依赖配置

## 二、代码修改清单

### 2.1 API URL 修改

**修改位置**: 所有 JS 文件中的 API 请求 URL

**修改内容**:

```javascript
// ❌ 本机（修改前）
url: 'http://localhost:9191/jobs'
// 或
url: 'http://localhost:9191/ese/services/ENVI/SpectralIndex/submitJob'

// ✅ 服务器（修改后）
url: 'http://192.168.0.19:9191/ese/services/ENVI/[TaskName]/submitJob'
```

**具体修改规则**:
1. 将 `localhost` 改为服务器 IP：`192.168.0.19`
2. 将 `/jobs` 改为正确的任务路径：`/ese/services/ENVI/[TaskName]/submitJob`
3. `[TaskName]` 替换为实际任务名称，例如：
   - `SpectralIndex`
   - `GSF_GF1_RadiometricCorrection`
   - `GSF_NDVITask`
   - `GSF_Change_Detection`
   - 等等

**示例**:

```javascript
// SpectralIndex 任务
url: 'http://192.168.0.19:9191/ese/services/ENVI/SpectralIndex/submitJob'

// GSF_GF1_RadiometricCorrection 任务
url: 'http://192.168.0.19:9191/ese/services/ENVI/GSF_GF1_RadiometricCorrection/submitJob'
```

### 2.2 数据文件路径修改

**修改位置**: 所有 JS 文件中的 `input_file` 或 `input_raster` 参数

**修改内容**:

```javascript
// ❌ 本机路径（修改前）
input_file: 'C:\\Works\\ENVITaskTrainning\\02_ENVITasks\\data\\beijing_miyun.dat'
// 或
input_raster: {
    url: 'http://localhost:9191/data/qb_boulder_msi',
    factory: 'URLRaster'
}

// ✅ 服务器路径（修改后）
input_file: 'D:\\FTPfiles\\GF1_PMS1_E113.3_N22.7_20240213_L1A13282365001\\GF1_PMS1_E113.3_N22.7_20240213_L1A13282365001-MSS1.xml'
// 或
input_raster: {
    url: 'D:\\Program Files\\NV5\\ENVI61\\data\\qb_boulder_msi',
    factory: 'URLRaster'
}
```

**注意事项**:
- Windows 路径中的反斜杠需要转义为 `\\` （ENVI Service Engine要求）
- 确保数据文件已上传到服务器对应路径
- 根据任务定义，使用 `input_file` 或 `input_raster`（查看 `.task` 文件确认）

### 2.3 参数格式调整

**根据任务定义调整参数名称和格式**

**常见修改**:

1. **参数名称**:
   ```javascript
   // 某些任务使用 input_file，某些使用 input_raster
   // 查看 .task 文件中的参数定义确认
   input_file: '...'  // 或
   input_raster: {...}
   ```

2. **移除 taskName 参数**:
   ```javascript
   // ❌ 不需要（URL 中已指定）
   data: {
       taskName: 'GSF_GF1_RadiometricCorrection',
       ...
   }
   
   // ✅ 正确格式
   data: {
       input_file: '...',
       ...
   }
   ```

3. **布尔值格式**:
   ```javascript
   // ❌ 错误（字符串）
   get_out_options: 'true'
   
   // ✅ 正确（布尔值）
   get_out_options: true
   ```

### 2.4 完整代码示例

## 四、环境配置

### 4.1 Node.js 安装

**安装位置**: `D:\Program Files\nodejs\`

**验证安装**:
```powershell
node -v
npm -v
```

**如果 npm 无法使用，重新安装 Node.js**:
1. 访问 https://nodejs.org/
2. 下载 Windows 安装包（LTS 版本）
3. 安装到 `D:\Program Files\nodejs\`（或默认路径）
4. 确保勾选"添加到 PATH 环境变量"

### 4.2 项目依赖安装

**位置**: `D:\GSF32\`

**操作步骤**:
```powershell
# 进入项目目录
cd D:\GSF32

# 初始化 package.json（如果还没有）
npm init -y

# 安装 axios 依赖
npm install axios
```

### 4.3 ENVI 任务编译

**重要**: 如果任务程序在 `.pro` 文件中，需要在 ENVI IDL 中编译

**编译步骤**:

1. **打开 ENVI IDL**

2. **编译程序**:
   ```idl
   ; 在 IDL 命令行中执行
   .compile "D:\Program Files\NV5\ENVI61\custom_code\GSF_GF1_RadiometricCorrection\GSF_GF1_RadiometricCorrection.pro"
   ```

3. **或者使用 RESOLVE_ROUTINE**:
   ```idl
   RESOLVE_ROUTINE, 'GSF_GF1_RadiometricCorrection', /COMPILE_FILE
   ```

4. **（可选）生成 .sav 文件**:
   ```idl
   .compile "D:\Program Files\NV5\ENVI61\custom_code\GSF_GF1_RadiometricCorrection\GSF_GF1_RadiometricCorrection.pro"
   .save, /ROUTINE, 'GSF_GF1_RadiometricCorrection', FILENAME='D:\Program Files\NV5\ENVI61\custom_code\GSF_GF1_RadiometricCorrection\GSF_GF1_RadiometricCorrection.sav'
   ```

**错误提示**:
如果遇到错误：`Unknown or invalid procedure wrapped by task`，说明程序未编译，需要执行上述编译步骤。

## 五、移植步骤

### 步骤 1: 准备服务器环境

1. **安装 Node.js**
   - 下载并安装 Node.js LTS 版本
   - 验证安装：`node -v` 和 `npm -v`

2. **创建项目目录**
   ```powershell
   mkdir D:\GSF32
   cd D:\GSF32
   ```

3. **安装项目依赖**
   ```powershell
   npm init -y
   npm install axios
   ```

### 步骤 2: 复制和修改代码文件

1. **复制 JS 文件到服务器**
   - 将本机的 JS 文件复制到 `D:\GSF32\`

2. **批量修改 API URL**（使用 PowerShell）:
   ```powershell
   cd D:\GSF32
   Get-ChildItem *.js | ForEach-Object {
       $content = Get-Content $_.FullName -Raw -Encoding UTF8
       # 替换 localhost 为服务器 IP
       $content = $content -replace 'http://localhost:9191', 'http://192.168.0.19:9191'
       # 替换 /jobs 为正确的任务路径（需要根据具体任务手动调整）
       # $content = $content -replace '/jobs', '/ese/services/ENVI/[TaskName]/submitJob'
       $content | Set-Content $_.FullName -Encoding UTF8
   }
   ```

3. **手动修改每个文件**:
   - 修改 API URL 中的任务名称
   - 修改数据文件路径为服务器路径
   - 根据任务定义调整参数格式

### 步骤 3: 部署任务文件

1. **复制任务文件到服务器**
   - 将 `.task` 和 `.pro` 文件复制到 `D:\Program Files\NV5\ENVI61\custom_code\[TaskName]\`

2. **编译任务程序**
   - 在 ENVI IDL 中编译 `.pro` 文件（见 4.3 节）

3. **重启 GSF 服务**（如需要）
   - 确保任务已注册到 GSF 服务

### 步骤 4: 准备数据文件

1. **上传数据文件到服务器**
   - 将需要处理的数据文件上传到服务器
   - 记录实际存储路径

2. **更新代码中的数据路径**
   - 修改 JS 文件中的数据路径为服务器实际路径

### 步骤 5: 测试运行

1. **测试单个任务**:
   ```powershell
   cd D:\GSF32
   node .\SpectralIndex.js
   ```

2. **检查作业状态**:
   - 在浏览器中打开：`http://192.168.0.19:9191/job-console/`
   - 查看作业执行日志

3. **验证输出结果**:
   - 检查输出文件是否生成
   - 验证输出结果是否正确

## 六、快速修改脚本

### 6.1 PowerShell 批量修改脚本

创建 `update_urls.ps1` 文件：

```powershell
# 批量修改 JS 文件中的 localhost 为服务器 IP
$files = Get-ChildItem -Path "D:\GSF32" -Filter "*.js"

foreach ($file in $files) {
    Write-Host "处理文件: $($file.Name)"
    $content = Get-Content $file.FullName -Raw -Encoding UTF8
    
    # 替换 localhost
    $content = $content -replace 'http://localhost:9191', 'http://192.168.0.19:9191'
    
    # 替换 /jobs 为通用路径（需要手动调整任务名称）
    $content = $content -replace '/jobs', '/ese/services/ENVI/[TaskName]/submitJob'
    
    Set-Content -Path $file.FullName -Value $content -Encoding UTF8
    Write-Host "完成: $($file.Name)"
}
```

**注意**: 脚本中的 `[TaskName]` 需要根据实际任务名称手动替换。

### 6.2 查询作业状态脚本

创建 `check_job.js` 文件：

```javascript
var axios = require("axios");

function checkJobStatus(jobId) {
    const statusUrl = `http://192.168.0.19:9191/ese/jobs/${jobId}/status`;
    
    axios.get(statusUrl)
        .then(function (response) {
            console.log('作业状态:', response.data.jobStatus);
            console.log('作业进度:', response.data.jobProgress + '%');
            console.log('进度消息:', response.data.jobProgressMessage);
            
            if (response.data.jobStatus === 'esriJobSucceeded') {
                console.log('\n✓ 作业执行成功！');
                console.log('结果:', JSON.stringify(response.data.results, null, 2));
            } else if (response.data.jobStatus === 'esriJobFailed') {
                console.log('\n✗ 作业执行失败！');
                console.log('错误信息:', response.data.jobErrorMessage);
            } else {
                console.log('\n作业仍在执行中...');
            }
        })
        .catch(function (error) {
            console.error('查询状态失败:', error.message);
        });
}

// 使用示例：查询作业 25 的状态
// checkJobStatus(25);

// 从命令行参数获取 Job ID
const jobId = process.argv[2];
if (jobId) {
    checkJobStatus(jobId);
} else {
    console.log('用法: node check_job.js [JobID]');
}
```

**使用方法**:
```powershell
node check_job.js 25
```

## 八、常见问题

### 8.1 npm 无法使用

**问题**: `Error: Cannot find module 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js'`

**解决**: 重新安装 Node.js，确保 npm 正确安装。

### 8.2 404 错误

**问题**: `Cannot POST /jobs` 或 `404 Not Found`

**解决**: 
- 检查 API URL 是否正确：`/ese/services/ENVI/[TaskName]/submitJob`
- 确认任务名称是否正确
- 检查 GSF 服务是否运行

### 8.3 任务程序未找到

**问题**: `Unknown or invalid procedure wrapped by task`

**解决**: 
- 在 ENVI IDL 中编译 `.pro` 文件
- 检查任务文件是否在正确位置
- 重启 GSF 服务

### 8.4 参数格式错误

**问题**: 作业提交成功但执行失败

**解决**: 
- 查看任务定义文件（`.task`）确认参数名称
- 检查参数类型（字符串 vs 布尔值）
- 查看作业日志获取详细错误信息
