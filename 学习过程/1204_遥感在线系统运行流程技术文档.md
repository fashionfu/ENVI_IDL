## 系统架构概述

### 技术栈

**后端**:
- Node.js + Express - Web服务器（8080端口）
- MongoDB - 数据库（27017端口）
- Socket.IO - 实时通信
- ENVI Services Engine - 影像处理引擎（9191端口）

**前端**:
- HTML + CSS + JavaScript
- jQuery + jQuery UI - UI框架
- jqGrid - 数据表格
- Leaflet - 地图显示
- Socket.IO Client - 实时通信
- Bootstrap - 响应式布局

### 系统端口

| 服务 | 端口 | 说明 |
|------|------|------|
| Web服务器 | 8080 | Node.js Express应用 |
| ENVI Services Engine | 9191 | ESE服务端口（默认） |
| MongoDB | 27017 | MongoDB数据库端口（默认） |

### 架构特点

1. **前后端分离架构**：前端直接调用ESE服务，Node.js后端负责业务逻辑
2. **混合调用模式**：任务提交直接调用ESE，状态管理通过Node.js
3. **实时通信**：使用Socket.IO进行系统资源监控

## 关键要点

### 1. 架构特点

#### 前后端分离架构
- **前端**：直接调用ESE服务（9191端口），不经过Node.js后端
- **后端**：Node.js（8080端口）负责业务逻辑、用户管理、文件管理、数据持久化
- **优势**：减少中间层，降低延迟，提高性能

#### 混合调用模式
- **任务提交**：前端 → ESE服务（直接调用）
- **状态管理**：前端 → Node.js后端 → MongoDB
- **文件管理**：前端 → Node.js后端 → 文件系统

### 2. 数据流向

#### 任务提交流程
```
用户操作
    ↓
前端JavaScript
    ↓
直接POST到ESE (9191端口)
    ↓
ESE处理任务
    ↓
返回jobId和状态URL
    ↓
前端轮询状态
    ↓
任务完成 → 保存结果到MongoDB
```

#### 文件管理流程
```
用户操作
    ↓
前端JavaScript
    ↓
POST到Node.js后端 (8080端口)
    ↓
后端处理（文件系统操作）
    ↓
返回结果
```

### 3. 关键技术点

#### Session管理
- 使用express-session管理用户会话
- Session存储在服务器端，通过Cookie传递Session ID
- Session有效期：60 * 1000 * 1000 毫秒（约16.7小时）

#### 任务状态持久化
- 任务提交时：保存基本信息（jobId、状态URL、时间戳）
- 任务完成时：保存完整结果（文件URL、地图范围等）
- 用户下次登录：自动恢复正在执行的任务

#### 实时通信
- 使用Socket.IO实现WebSocket通信
- 系统资源监控：每10ms推送一次数据
- 支持多客户端同时连接

#### 轮询机制
- 任务状态轮询：每1秒查询一次
- 使用递归调用实现持续轮询
- 任务完成后停止轮询

#### 文件访问

### C. 常见问题

#### Q1: 任务提交失败怎么办？
**A**: 检查ESE服务是否运行，检查任务参数是否正确，查看ESE日志。

#### Q2: 轮询一直显示执行中？
**A**: 可能是ESE服务异常，检查ESE服务状态，查看任务日志。

#### Q3: 文件上传失败？
**A**: 检查上传目录权限，检查磁盘空间，检查文件大小限制。

#### Q4: 无法连接MongoDB？
**A**: 检查MongoDB服务是否启动，检查连接地址和端口，检查防火墙设置。
